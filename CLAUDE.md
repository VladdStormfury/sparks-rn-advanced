# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ShelfScan: an Expo/React Native app (Expo SDK 58, RN 0.88, React 19.3) that scans a book's ISBN barcode, fetches its record from the Open Library API, and keeps a personal offline library. It is the reference project for a 2-day "React Native avancé" training; this checkout (`solution/m3` content) has TanStack Query, MMKV persistence, and a feature-based architecture already applied — see `AGENTS.md` for Expo-specific rules (always check the installed Expo major version against docs before using any Expo/RN API) and `README.md` for the full branch progression and the Apple-silicon simulator workaround.

## Commands

```bash
npm install
npx expo start               # dev server
npx expo run:android         # native build + run on Android
npm run ios:simulator -- --device "iPhone 17"   # iOS simulator (Apple silicon), see README for why
npx expo run:ios --device    # real iPhone (camera scanning only works on-device)
npx tsc --noEmit             # typecheck
npx expo lint                # lint
npm test                     # jest
npx jest path/to.test.ts -t "test name"   # single test
npx stryker run              # mutation testing (targets src/features/*/services/**)
```

Use `npx expo install <package>` instead of `npm install` for any new dependency, to resolve SDK-58-compatible versions. `android/` and `ios/` are generated by Expo prebuild (Continuous Native Generation) and are not versioned — never hand-edit them; configure native behavior via `app.json`/config plugins instead.

Always run typecheck, lint, and tests before considering a task done.

## Architecture

**Routing**: Expo Router. Every file under `src/app/` is a screen; `_layout.tsx` files define navigators. `src/app/_layout.tsx` wraps the whole app in `AppProviders` (TanStack Query) and declares the root `Stack` (tabs + `book/[isbn]` detail route). Tabs (Scan, Search, Library) live under `src/app/(tabs)/`. Keep non-route code (components, hooks, services) out of `src/app/` — those files should just import a screen component from `src/features/*/screens/`.

**Feature-first layout**: code is organized by feature under `src/features/{scan,book,search,library}/`, each with its own `components/`, `hooks/`, `screens/`, `services/`, `types/` (and `stores/` for library). Convention: no cross-feature imports — shared logic that multiple features need lives in `src/hooks/`, `src/lib/`, or `src/services/` instead, not borrowed from a sibling feature folder.

**Data layer (TanStack Query + MMKV)**:
- `src/lib/queryClient.ts` configures the single `QueryClient` (retries disabled for `BookNotFoundError`, 7-day `gcTime`) and calls `registerLibraryMutationDefaults` at module load.
- `src/lib/queryPersister.ts` persists the query cache to MMKV (`createSyncStoragePersister`); `AppProviders` (`src/components/AppProviders.tsx`) wires it up via `PersistQueryClientProvider` and triggers `syncLibraryAfterRestore` on successful cache restore.
- `src/lib/queryLifecycle.ts` hooks TanStack Query's `onlineManager`/`focusManager` to NetInfo and `AppState`, enabling offline pause/resume of queries and mutations.
- `src/lib/libraryMutations.ts` defines the "add to library" mutation as a **mutation default** (`setMutationDefaults`, keyed by `addToLibraryMutationKey` from `src/lib/libraryKeys.ts`) rather than inline in a hook. This is required for `resumePausedMutations()` to replay an offline "add" after the app is killed and relaunched — a plain `useMutation` call wouldn't survive that. Optimistic update + rollback happens here (`onMutate`/`onError`/`onSettled`), not in the UI hook.
- `src/lib/bookQuery.ts` / `src/lib/libraryQuery.ts` define `queryOptions()` factories per entity; feature hooks (e.g. `src/hooks/useBook.ts`, `src/features/library/hooks/useLibrary.ts`) just call `useQuery`/`useInfiniteQuery` with these options — keep query key/fetcher logic in the `lib/*Query.ts` files, not duplicated in hooks.
- Search pagination (`src/features/search/hooks/useSearchBooks.ts`) uses `useInfiniteQuery`.

**Services + typed errors**: each external boundary (Open Library HTTP API, MMKV-backed library storage, native scan feedback module) is wrapped in a `static`-method service class that normalizes failures into a subclass of `AppError` (`src/errors/AppError.ts`): `OpenLibraryError`/`BookNotFoundError`, `StorageError`, `ScanFeedbackError`. DTOs from the API are mapped to domain types (`src/types/book.types.ts`) inside the service, not in components/hooks. Follow this service-class + `AppError` subclass pattern for any new external integration.

**Local native module**: `modules/scan-feedback` is a local Turbo Module (autolinked via `file:./modules/scan-feedback` in `package.json`) exposing `vibrate(durationMs): Promise<void>` and `getDeviceModel(): string` (Kotlin on Android, Swift on iOS). `react-native.config.js` conditionally excludes it from iOS autolinking when `SHELFSCAN_IOS_SIMULATOR=1` is set, because its barcode-scanner sibling dependency ships an arm64-device-only ML Kit slice that fails to link on Apple-silicon simulators.

**Barcode scanning**: `react-native-vision-camera` + `react-native-vision-camera-barcode-scanner`. `IsbnService` (`src/features/scan/services/IsbnService.ts`) validates ISBN-10/13 checksums and filters scanned EAN-13 barcodes to the `978`/`979` book prefixes — this is the class under mutation testing, so changes here need accompanying tests.

**State**: Zustand (`src/features/library/stores/libraryStore.ts`) is used only for local UI state (library sort key), not server/cache data — that stays in TanStack Query.

## Testing

- `jest-expo` preset; `jest.setup.ts` mocks native modules (`react-native-scan-feedback`, `expo-device`, `react-native-vision-camera*`, `react-native-nitro-modules`, NetInfo) and starts the MSW server (`src/mocks/server.ts` + `src/mocks/handlers.ts`, which mock the Open Library `isbn` and `search` endpoints, including 404/500 and paginated cases).
- Mutation testing via Stryker is scoped to `src/features/*/services/**/*.ts` (excludes `__tests__` and `*.test.ts`); run `npx stryker run` and check `reports/mutation/index.html`.
- Maestro E2E flows live in `src/maestro/*.yml`.
